01／ THE PROBLEM

面談はできている。
それでも、決まらない。

面談の記録は増えました。それでも決定率が上がらないのは、残っている情報が違うからです。

  • 何を話したかは残る議事録も要約も手に入る時代です。
  • なぜ決めないかは残らない迷いの理由は、担当者の記憶の中にしかありません。
  • 担当が変わると消える引き継ぎの瞬間に、求職者理解がゼロに戻ります。
  • 辞退理由が溜まらない「他社で決まりました」の一行で終わっています。

記録されているのは、面談の中身です。
足りないのは、求職者の意思決定です。

04／ DECISION JOURNEY

一面談で、
終わらせない。

開発中

初回面談だけを解析しても、意思決定は見えません。同じ求職者として、承諾または辞退まで追いかけます。

初回面談求人提案応募選考内定承諾 / 辞退

各フェーズで更新するもの：

  • 意思決定軸の変化重視するものは、選考が進むほど動きます。
  • 不安の変化解消された懸念と、新しく生まれた懸念。
  • 志望度の変化どの時点で下がったのか。
  • 競合状況他社の選考がどこまで進んでいるか。
  • 次に解消すべき論点いま、何から手をつけるべきか。

一人の求職者に、一本の意思決定の履歴を。

05／ NEXT BEST ACTION

次の一手を、
毎回出す。

開発中

「求人を送る」「次回面談を設定する」ではありません。意思決定を前に進める一手を出します。

  • 次回面談で、働き方の懸念を先に確認する。
  • A社との比較軸を整理して提示する。
  • 家族への相談状況を確認する。
  • 年収ではなく、仕事内容から求人を再提案する。
  • 内定後に、評価制度の説明を追加する。

出すのは指示ではなく、材料です。決めるのはCAです。

06／ CA GROWTH

決定率を上げながら、
CAが育つ。

開発中

トップCAと話し方が似ているかは見ません。求職者の意思決定を前に進める介在ができたかを見ます。

  • 転職理由の深掘り―なぜ動きたいのかを、言葉にできたか。
  • 意思決定軸の言語化―何で決めるのかを、本人と確認できたか。
  • Must / Want の整理―譲れないものと、あれば嬉しいものを分けられたか。
  • 未解消懸念の検知―口に出されていない不安に気づけたか。
  • 現職残留要因の把握―残る理由を、正面から聞けたか。
  • 反応に応じた質問変更―相手の反応を見て、聞き方を変えられたか。
  • 次アクションの合意―次に何をするかを、その場で決められたか。

人事評価や査定には使いません。目的はCAを採点することではなく、求職者をより深く理解し、より良い介在ができるようにすることです。スコアは実際のデータが貯まった分だけ表示し、データのない項目は空欄のままにします。

チームとして、学習する。設計済み

  • 組織全体の意思決定支援力

07／ HOW IT WORKS

録音から、
Outcomeまで。

01面談を録音する普段どおり面談します。やり方を変える必要はありません。
02構造化する転職理由、Must / Want、懸念、制約を項目に分解します。
03意思決定を分析するいま何で止まっているのか、何が解消されれば進むのかを出します。
04次アクションを出す次の面談までに解消すべき論点を提示します。
05Outcome とつなぐ応募・選考・内定・承諾・辞退・辞退理由・入社後定着まで記録します。
06どの介在が効いたかを学ぶOutcome から遡って、前に進めた介在を特定します。

DATA MODEL設計済み

求職者状況求職者の反応CAの介在意思決定Outcome

面談単位ではなく、求職者単位で履歴がつながる設計です。だから「どの介在が、どのOutcomeにつながったか」を後から追えます。
