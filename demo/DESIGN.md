# デモのデザイン指針

`media/demo/` に置くサービスデモ（画面イメージ）を作るときの共通ルールです。
最初の例は `demo/hotel-tax/`（宿泊税クラウド）です。迷ったらこれに合わせてください。

---

## 1. デモの役割

デモは、商談の相手が「これなら自分たちの業務で使える」と思えるかを確かめるためのものです。
製品を完成させることでも、機能を全部見せることでもありません。

- 相手の**月の流れ（業務の順番）**に沿って、画面が並んでいること
- 開いた瞬間に**いま何をすればいいか**が分かること
- 細かい根拠は、聞かれたときに**一段下を開けば出てくる**こと

---

## 2. 5つの原則

1. **1画面に目的は1つ。次にやることも1つ**
   主ボタンは1画面に1つ。いまのステップにだけ置きます。
2. **まとめが先、詳細はあと**
   最初に見えるのは数字と状態だけにします。計算の根拠や設定はモーダル、折りたたみ、タブの中に入れます。
3. **色は「状態」にだけ使う**
   紺は見出しと主ボタン、青緑は選択中と完了、オレンジは「要確認」など相手が手を動かす所だけに使います。完了は「✓」で示します。
4. **相手の現場の言葉で書く**
   システムの言葉（ステータス、レコード、バリデーションなど）は使いません。
   例：「ステータス：未処理」ではなく「要確認」。「チャネル設定」ではなく「宿泊税の受け取り方」。
5. **動いている状態から始める**
   空の画面は見せません。実案件と同じくらいの規模の架空データを、最初から入れておきます。

---

## 3. 情報量の上限

「多すぎる」と感じさせないための目安です。これを超えるときは、画面を分けるか、一段下に移してください。

| 場所 | 上限 |
| --- | --- |
| 上部のナビ | 6項目 |
| ホームの大きな数字 | 3つ |
| 一覧の表 | 5列（それ以上は行を押して開く詳細へ） |
| 絞り込み | 検索欄＋選択2つ |
| 主ボタン | 1画面に1つ |
| 注記・免責 | ページ下のフッターに1か所（帳票の中は例外） |
| 1行の説明文 | 1〜2文。段落にしない |

---

## 4. 「AIっぽく」見えるので使わないもの

- 絵文字やアイコンを見出しの飾りに使う
- 色付きのラベル（ピル）を表のあちこちに並べる
- 大きな数字のカードを4枚以上並べる
- 濃い色のサイドバーと、グラフだらけのダッシュボードの組み合わせ
- グラデーション、影、大きな角丸を全部の箱に付ける
- 01 / 02 / 03 のような飾りの番号（本当に順番がある流れにだけ番号を付ける）
- 「〜を実現」「シームレスに」「次世代の」のようなコピー
- 同じ注意書きを各画面に繰り返す

---

## 5. 画面の型

デモはこの5つの型の組み合わせで作ります。新しい型は、どうしても必要なときだけ足してください。

| 型 | 使いどころ | 作り方 |
| --- | --- | --- |
| **ホーム** | 最初に開く画面 | 月の流れをチェックリストで縦に並べる（完了 ✓ ／ いまここ ／ これから）。いまのステップにだけボタン。その下に数字を3つまで |
| **一覧** | 予約、物件など | 絞り込み＋表＋ページ送り。行を押すとモーダルで詳細 |
| **確認作業** | 人の判断が要るもの | 左に一覧、右に1件分。項目は質問の形にし、選択肢を並べる。選んだ結果をその場で見せ、「確定して次へ」で次の1件へ |
| **帳票** | 明細、集計表など外に出すもの | 紙に見える白い面。表題、宛名、合計、内訳、前提、注記の順に並べる。PDFは白い紙で出力する |
| **設定** | ルール、マスタ | タブで分ける。普段は触らない場所にまとめる |

---

## 6. 見た目の決まり

### 色

資料のグランドデザイン（`slides/FORMAT.md` 6節）と同じ、**紺・青緑・オレンジ**の配色にします。商談で資料からデモに移ったときに、同じ製品に見えるようにするためです（会社サイト本体はティールのままです）。**ふだんは白を基調にした明るい画面**にし、見る人の端末がダークモードのときだけ、紺をもとにした暗い配色に切り替えます。

| 色 | 値 | デモでの役割 |
| --- | --- | --- |
| 紺 | `#14304f` | `--deep` 見出し（h1・h2）、帳票の表題の下線 ／ `--primary` 主ボタン、選択中のセグメント |
| 青緑 | `#0b7a7c` | `--accent` 選択中のタブ・項目、リンク、完了の ✓、いまのステップ |
| オレンジ（文字） | `#9a4a12` | `--warn` 「要確認」など相手が手を動かす所 |
| 本文 | `#1f2933` | `--ink` |
| 補足の文字 | `#5b6773` | `--sub` |
| 線 | `#d8dee4` | `--line` |
| 薄い背景 | `#f6f8fa` | `--bg` 合計の枠、表の区切り行など一部の面 |
| 白 | `#ffffff` | `--page` ページの地、`--paper` 表や入力欄の面 |

青緑は資料の `#0F8B8D` より少し濃い `#0b7a7c` にしています。資料の色のままだと、白地の小さな文字で 4.5:1 に届かない（4.1:1）ためです。

このまま `:root` に貼ってください。

```css
:root{
  color-scheme:light;
  --page:#ffffff; --bg:#f6f8fa; --paper:#ffffff; --ink:#1f2933; --sub:#5b6773; --faint:#77838f; --line:#d8dee4; --hover:#f3f6f8;
  --accent:#0b7a7c; --accent-weak:#e3f3f3; --on-accent:#ffffff; --deep:#14304f; --scrim:rgba(20,48,79,.45);
  --primary:#14304f; --on-primary:#ffffff;
  --warn:#9a4a12; --warn-weak:#fdf0e6; --ok:#0b7a7c; --ng:#b8432f;
  --font:"Inter","Noto Sans JP",system-ui,-apple-system,"Hiragino Sans","Yu Gothic",sans-serif;
}
/* ダークモード：真っ黒にせず、紺をもとにした暗い色にする */
@media (prefers-color-scheme: dark){ :root:not([data-theme="light"]){
  --page:#0f1e2e; --bg:#1a2c40; --paper:#152638; --ink:#e6edf3; --sub:#a9b6c3; --faint:#7f8e9c; --line:#2a3d52; --hover:#1c3046;
  --accent:#5cc8c9; --accent-weak:#173f47; --on-accent:#06222a; --deep:#9db4cc; --scrim:rgba(0,0,0,.55);
  --primary:#7fd3d4; --on-primary:#0b1c2b;
  --warn:#f0a066; --warn-weak:#3d2614; --ok:#5cc8c9; --ng:#f39484; color-scheme:dark;
}}
/* 同じ値を :root[data-theme="dark"]{ … } にも書く */
body{ background:var(--page); }
h1,h2{ color:var(--deep); }
.btn.pri{ background:var(--primary); border-color:var(--primary); color:var(--on-primary); }
```

- 主ボタン（`.btn.pri`）は紺の地に白い文字（`--primary`）。1画面に1つ
- 青緑（`--accent`）は、選択中のタブ・項目、リンク、完了の ✓、いまのステップだけに使います。面を塗りつぶす使い方はしません
- 完了を表す色は青緑にします。緑をもう1色増やさないためです
- `--warn`（オレンジ）は「要確認」と、相手が判断すべき所だけに使います
- `--ng`（赤）は「未設定」など、このままだと計算できない所だけに使います
- 文字と背景のコントラストは 4.5:1 以上を守ります（白地の紺 13.4:1、青緑 5.1:1、オレンジ 6.3:1）。`--faint` は飾りの小さな文字だけに使い、注記や免責には `--sub` を使います
- 色は直接書かず、必ずこの変数を使います（あとで色を変えるときに1か所で済むように）。PDF用の `.pdf-doc` だけは、画面のテーマに関係なく白い紙にするため値を直接書きます

### 文字

| 用途 | サイズ | 太さ |
| --- | --- | --- |
| 画面の見出し | 20px | 700 |
| 区画の見出し | 15px | 700 |
| 本文・表 | 13.5〜14px | 400 |
| 補足・注記 | 12〜12.5px | 400（`--sub` の色） |
| 大きな数字 | 26px（帳票の合計は28px） | 700 |

- フォントは会社サイトと同じ Inter（英数字）＋ Noto Sans JP（日本語）。どちらも Google Fonts
- 数字は `font-variant-numeric: tabular-nums` で桁をそろえる
- 金額は「83,000円」のように、3桁ごとのカンマと単位を付ける

### 余白・形

- 本文の最大幅は 1080px。左右の余白はスマホでも16px以上
- 区画どうしの間は 28px、箱の内側は 20〜22px
- 線は 1px（`--line`）。影は使わない
- 角丸は 箱 8px ／ ボタン・入力 6px ／ 帳票 4px

## 7. 部品

`demo/hotel-tax/index.html` にあるものを使い回します。

| 部品 | クラス | メモ |
| --- | --- | --- |
| ヘッダーとタブ | `.top` `nav` | サービス名＋「画面イメージ」の表記。スマホでは横にスクロール |
| 流れのチェックリスト | `.steps` | `done` / `now` / `wait` の3状態 |
| 数字の行 | `.stats` `.stat` | 最大3つ。下に1行の補足 |
| 表 | `.tw` `table` | 押せる行は `tr.click` |
| 状態の表示 | `.st-warn` `.st-ok` | 「要確認」はオレンジの文字、「確定」は灰色の文字に青緑の ✓。ラベルの箱にしない |
| ボタン | `.btn` `.btn.pri` `.btn.ghost` | 主ボタンは1画面に1つ |
| 選択肢 | `.opt` | ラジオボタンを箱にしたもの。選ぶと薄い青緑になる |
| 結果の表示 | `.result` | 「この内容で確定すると ○円」 |
| 帳票 | `.doc` | PDF用には `.pdf-doc` を足す（白い紙に固定） |
| モーダル、通知 | `.modal` `.toast` | 確認の画面はモーダルにせず、ページの中に置く |

## 8. 文言

- です・ます調で、短く書きます
- ボタンは「何が起きるか」を動詞で書きます：「確定して次へ」「PDFをダウンロード」「今月分を確定」
- 人の判断が要る所は質問の形にします：「『追加料金 2,000円』は清掃料ですか？」
- 選択肢のうち推奨するものには「（おすすめ）」を付けます
- 運営会社は「貴社」、その顧客は「オーナー様」のように、相手の立場で呼びます
- 断定できない数字は断定しません。条件と件数を添えます：「預かった額との差（データで確認できた412件のみ）」
- 法的な注意（例：税務代理は行わない）は、フッターと帳票の中にだけ書きます

---

## 9. 架空データ

- 固定のシード値を使う乱数で、毎回同じデータを作ります（説明中に数字が変わらないように）
- 規模は実案件と同じくらいにします（例：144物件、約900件の予約）
- 実在の会社名、人名、ゲスト名、お客様の名前は使いません。ゲストの個人情報にあたる項目はデータに持たせません
- 対象月は「開いた日の前月」にし、いつ開いても今月の話として見えるようにします
- 週末は料金を上げるなど、現場らしいばらつきを入れます
- 要確認のような「人が見るべきもの」は、全体の5%前後にします（多すぎると説明が終わらない）

---

## 10. 作り方の決まり

- HTML 1ファイルで完結させます（`demo/<名前>/index.html`）
- 外部の読み込みは Google Fonts だけにします。ライブラリ（例：PDF作成）は、ボタンを押したときに cdnjs から読み込みます
- 画面の切り替えは `#home` のような URL の `#` で行い、リンクで特定の画面を送れるようにします
- 操作の結果は `localStorage` に保存し、読み書きは try/catch で囲みます。フッターに「デモを最初の状態に戻す」を置きます
- スマホ幅（約400px）とダークモードで崩れないこと
- `<meta name="robots" content="noindex, nofollow">` を必ず入れます
- `alert()` や `confirm()` は使わず、通知（toast）とページ内の確認で済ませます

---

## 11. 公開

1. `demo/<名前>/index.html` を作ります。名前は英小文字とハイフンで付けます（例：`hotel-tax`）
2. 本番のブランチ `claude/b2b-homepage-design-cl39bk` にコミットして push します
3. 1〜2分後に `https://www.vitality-design.jp/demo/<名前>` で確認します

`vercel.json` の設定で、`/demo/<名前>` で開けること、検索に載らないことは対応済みです。
特定のお客様だけに見せるデモは、推測されにくい名前にして、サイトからリンクしないでください。

## 12. 商談前のチェックリスト

- [ ] ホームを開いて3秒で「次に何をするか」が分かる
- [ ] 主ボタンが各画面に1つだけ
- [ ] 表が5列以内、数字が3つ以内に収まっている
- [ ] 色が付いているのは「要確認」「未設定」と主ボタン、選択中の所だけ
- [ ] 色の値を直接書いていない（`.pdf-doc` を除く）
- [ ] 実在の名前やお客様の名前が入っていない
- [ ] スマホとダークモードで崩れない（ダークモードでも文字が読みやすい）
- [ ] 帳票のPDFを実際にダウンロードして、右端まで入っている
- [ ] 「デモを最初の状態に戻す」を押してから商談に入る
