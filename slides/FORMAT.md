# 資料のフォーマット

Vitality Design の資料を同じ型でつくるための決まりです。
迷ったらこのフォルダのひな形（`deck-16x9.html` / `paper-a4.html`）と、`docs/doc-p2.png`（FIELD CX の2ページ目）に合わせてください。

---

## 1. 資料の役割

資料は、相手に**1つのことを決めてもらう**ためのものです。説明を全部載せる場所ではありません。

- 1冊につき「読んだ人に決めてほしいこと」は1つ（例：15分の打ち合わせを入れる、診断を頼む）
- 1ページにつき「言いたいこと」は1つ。それを見出しに1文で書く
- 根拠は、見出しのすぐ下に置く。細かい数字は表か、巻末の「前提と注記」へ

---

## 2. 5つの原則

1. **見出しは結論の1文にする**
   「課題」「サービス概要」のようなラベルを見出しにしません。
   ✕「継続の課題」 ○「継続は、4つの瞬間で切れます。」
2. **ページの流れは相手の順番で**
   相手が困っていること → なぜ起きるか → どう変わるか → 何をするか → いくらで・どこまで → 次の一歩。
   自社紹介は最後にします。
3. **色は役割で決める。オレンジは1ページ1か所**
   紺＝見出しと表の見出し行、青緑＝ラベル・番号・強調の一行、オレンジ＝見出しのキーワード1か所。本文の強調は太字にし、色を付けません。
4. **相手の現場の言葉で書く**
   「DX」「ソリューション」「最適化」ではなく、相手が毎日使う言葉で書きます。
   ✕「予約データの一元管理を実現」 ○「予約の確認を、毎朝ひとつの画面で終えられます」
5. **言えないことは書かない**
   実績・成果・製品について、事実として言えないことは書きません（→ 8節）。

---

## 3. 判型

| 判型 | サイズ | 使うとき | ひな形 |
| --- | --- | --- | --- |
| **スライド 16:9** | 1920×1080px（PDF: 297×167mm） | 画面に映す、オンライン商談で共有する | `deck-16x9.html` |
| **A4縦** | 210×297mm | メールで送る、印刷して渡す、読み物として渡す | `paper-a4.html` |

- 枚数の目安：スライドは **8〜12枚**、A4は **4〜8ページ**（表紙を除く）
- これを超えるときは、資料を2つに分けるか、付録に回します

---

## 4. ページの型

資料はこの型の組み合わせでつくります。新しい型は、どうしても必要なときだけ足してください。
ひな形には全部の型が入っています（クラス名は `deck-16x9.html` のもの）。

| 型 | クラス | 中身 | 使いどころ |
| --- | --- | --- | --- |
| **表紙** | `.s-cover` | 上にラベル（`VITALITY DESIGN ／ 〇〇向け`）、中央に結論のコピー2行、下に会社名と連絡先 | 1枚目。暗い地 |
| **結論** | `.s-key` | 大きな1文＋補足1〜2文 | 2枚目に「この資料で言いたいこと」を置く |
| **表** | `.s-table` | 見出し＋リード＋表（4列×5行まで）＋表の下に1段落 | 課題の整理、場面ごとの比較。いちばんよく使う |
| **流れ** | `.s-flow` | 見出し＋横並びのステップ（3〜5個） | 業務の順番、進め方、導入の流れ |
| **数字** | `.s-stats` | 見出し＋数字3つまで＋それぞれに1行の説明＋出典 | 調査結果、規模感 |
| **画面** | `.s-shot` | 見出し＋画面の画像1枚＋説明の箇条書き3つまで | デモ・画面イメージの紹介 |
| **プラン** | `.s-plan` | 見出し＋比較表（3案まで、おすすめ1列だけ薄い地）＋費用の注記 | 提供範囲、費用、期間 |
| **次の一歩** | `.s-next` | 相手にしてほしいこと1つ＋連絡先 | 最後のページ |
| **前提と注記** | `.s-notes` | 箇条書き。データの出どころ、架空である旨、保証しないこと | 末尾。注記はここにまとめる |

### 決まった並び（迷ったらこの順）

**サービス紹介資料（A4・6ページ）** — FIELD CX の構成
表紙 → 01 いま起きていること → 02 設計対象（表） → 03 やること（流れ） → 04 進め方 → 05 プラン → 06 次の一歩・会社情報

**調査レポート（A4・4〜6ページ）** — 89件レポートの構成
表紙（件数と方法を副題に） → 調べ方（数字） → 分かったこと①〜③（表） → 現場でできること → 前提と注記

**商談用スライド（16:9・10枚）**
表紙 → 結論 → 相手の今の流れ（流れ） → 手間がかかっている所（表） → 変わったあとの流れ（流れ） → 画面 ×2 → 進め方 → プラン → 次の一歩

## 5. ページの部品

すべてのページ（表紙以外）は、上から次の順に並べます。

```
宿泊税クラウド                     ← 資料名（小さいラベル。左上。--faint）
[02] ／ 設計対象                   ← 章番号（青緑の地に白抜き）／ 章名（青緑の太字）
継続は、4つの瞬間で切れます。          ← 見出し（結論の1文。紺。キーワード1か所だけオレンジ）
「また来てください」と…              ← リード（1〜2文。大事な所だけ太字）

[ 本文：表・流れ・数字・画面のどれか1つ ]

┃本日：〇〇を一緒に決めます。          ← 強調の一行（必要なときだけ。薄い青緑の面＋左に青緑の線）
───────────────
費用は、対象となる…                 ← 注記（そのページに必要な場合だけ。小さい文字）
                              2  ← ページ番号（右下）
```

- 本文の部品は **1ページに1つ**。表と流れを同じページに並べません
- 表の見出し行は**紺の地に白い太字**。1列目は紺の太字。縦線は引かず、行の間は `--line` の横線だけ
- 比較表の「あり／なし」は `●` と `—`。✓や色付きのラベルは使いません
- カード（事実の並び・役割の比較など）は `--tint` の面に、上辺だけ4pxの色の帯（青緑か紺）。いちばん伝えたい1枚だけ青緑で塗り、白い文字にしてよい
- 計算の結果など「答え」は、薄いオレンジの面（`--tint-orange`）に濃いオレンジ（`--orange-ink`）の太字。1資料に数か所まで

## 6. 見た目の決まり

### 色

紺・青緑・オレンジの3色で組みます。宿泊税クラウドのご紹介資料・提案資料（2026年11月）の配色が見本です（お客様向けの資料なので、このリポジトリには置いていません）。**資料ごとに色を変えません。**

```css
:root{
  --paper:#FFFFFF;   /* 本文ページの地 */
  --navy:#14304F;    /* 見出し・表の見出し行の地・表の1列目（中心の色） */
  --teal:#0F8B8D;    /* 章番号・ラベル・ステップ番号・数字・強調の一行 */
  --orange:#E8833A;  /* 見出しのキーワード（1ページ1か所）・表紙のコピー2行目・表紙の短い線 */
  --orange-ink:#9A4A12; /* 薄いオレンジの面に載せる文字 */
  --ink:#1F2933;     /* 本文 */
  --sub:#5B6773;     /* リード・補足・注記 */
  --faint:#8A96A3;   /* ページ番号・資料名ラベルなど飾りの小さな文字だけ */
  --line:#D8DEE4;    /* 表の横線・枠 */
  --tint:#F6F8FA;    /* カードの面・表の1行おき */
  --tint-teal:#E3F3F3;   /* 強調の一行の面 */
  --tint-orange:#FDF0E6; /* 計算結果など「答え」の面 */
  --dark:#14304F;    /* 表紙の地（紺 → 青緑のグラデーション） */
  --dark-2:#0F8B8D;
  --on-dark:#FFFFFF; --on-dark-2:#D5E2EC;
}
```

| 色 | 使う所 | 使わない所 |
| --- | --- | --- |
| 紺 `--navy` | 見出し、表の見出し行（白い文字）、表の1列目、カードの見出し | 本文 |
| 青緑 `--teal` | 章番号の地、章名、ステップ番号、大きな数字、強調の一行、デモへのリンク | 見出し全体 |
| オレンジ `--orange` | 見出しのキーワード **1ページ1か所**、表紙のコピー2行目と短い線、流れの「いまここ」の線 | 本文、表の中、1ページに2か所以上 |

- 文字と地のコントラストは 4.5:1 以上。`--faint` を本文や注記に使わない
- オレンジの文字は白地か紺地にだけ置く。青緑の地には置かない
- 色は直接書かず、必ず変数を使う

### 文字

資料は見出しも本文も **Noto Sans JP**（英数字は Inter）。過去の資料と同じです。
明朝（Shippori Mincho）は、ブランド寄りの表紙のコピーにだけ使ってかまいません。

| 用途 | 16:9（1920px 基準） | A4 | 太さ |
| --- | --- | --- | --- |
| 表紙のコピー | 96px | 30pt | 700 |
| 見出し | 56px | 20pt | 700 |
| リード | 28px | 10.5pt | 400（`--sub`） |
| 本文・表 | 24〜26px | 9.5〜10pt | 400 |
| 表の見出し行・ラベル | 18〜20px | 8pt | 500（`--sub`） |
| 注記 | 18px | 7.5pt | 400（`--sub`） |
| 大きな数字 | 120px | 36pt | 700 |

- 行間：本文 1.8、見出し 1.4
- ラベル（`FIELD CX`、`VITALITY DESIGN`）は Inter の大文字、字間 .16em
- 数字は `font-variant-numeric: tabular-nums`、金額は「83,000円」

### 余白・形

- 16:9：左右 120px、上 96px、下 80px。A4：左右 18mm、上 16mm、下 14mm
- 影・角丸の箱は使わない。線は 1px（カード上辺の帯だけ 4px）
- グラデーションは表紙の地（紺 → 青緑、左上から右下）だけ
- 画像（画面のスクリーンショット）だけ角丸 8px と 1px の枠

## 7. 書き方

- です・ます調。1文は40字まで。リードは2文まで
- 見出しは「〜です／〜ます／〜できます。」で終わる1文。体言止めのラベルにしない
- 太字は1段落に1か所まで。「ここだけ読めば分かる」所に付ける
- 相手の呼び方を決めて統一する（「貴社」「オーナー様」「候補者さん」など）
- 数字には単位と条件を付ける：「89件」「面談の録音を1件ずつ聞いた」「確認できた412件のみ」
- 費用は書ける場合だけ書く。書けない場合は「個別見積」と、何で決まるかを1文で
- 使わない言葉：「〜を実現」「シームレス」「次世代」「革新的」「ワンストップ」「圧倒的」「DX推進」

### 「AIっぽく」見えるので使わないもの

`demo/DESIGN.md` §4 と同じです。

- 見出しの頭の絵文字・アイコン
- 色付きのラベル（ピル）を並べる
- 大きな数字のカードを4枚以上並べる
- 3つの箱にアイコン＋見出し＋説明を並べるだけのページ（中身のない「3つの特長」）
- 表紙以外のグラデーション、影、大きな角丸
- 本当の順番がないのに 01 / 02 / 03 の番号を付ける
- 同じ注意書きを毎ページに繰り返す

## 8. 書いてよいこと・いけないこと（必ず守る）

`README.md` §8 のルールを資料にも適用します。

**書いてはいけないこと**

- 導入企業名、顧客ロゴ、お客様の声、売上・顧客数・資金調達の実績（**まだ存在しないため**）
- 改善効果（ADR、稼働率、成約率など）を実証済みの成果として書くこと
- 構想段階のもの（`Experience OS` など）を、提供中の製品として書くこと
- 代表が宿泊業界の出身であるように読める書き方
- 画面イメージ・コンセプト画像を、実際の導入事例として見せること

**書くときに必ず添えること**

| 書く内容 | 添える文言（例） |
| --- | --- |
| デモの画面 | 「画面イメージです。データはすべて架空です。」 |
| 調査の数字 | 調べた件数・期間・方法。「〇件の面談の録音を1件ずつ聞いた結果です。」 |
| 見込みの効果 | 「見込みであり、成果を保証するものではありません。」 |
| 構想 | 「構想段階であり、完成した製品として提供している段階ではありません。」 |
| 税・法律が関わるもの | 「税務代理・法律相談は行いません。」 |

- 注記は**末尾の「前提と注記」ページか、そのページの下に1か所**。毎ページに繰り返さない
- 実在の会社名・人名・お客様名は、相手の許可なく入れない。例は架空の名前にする

## 9. 会社情報（表紙・最終ページ用）

`llms.txt` と同じ内容を使います。ここ以外の書き方をしないでください。

```
VITALITY DESIGN LLC
バイタリティデザイン合同会社
vitality-design.jp ・ contact@vitality-design.jp
```

所在地・代表名を入れる場合は `llms.txt` からそのまま写します。
